    3. Les composants

    Jusqu'ici, chaque exemple tenait dans un seul composant, [App.vue]. Une vraie application en compte des dizaines : une barre de navigation, des formulaires, des fenêtres... Chaque composant est un morceau d'interface autonome (son HTML, son code, son style) et réutilisable. Ce chapitre montre comment les composants s'emboîtent et communiquent.

    <!--
  =========================================================================
  07-composants/src/components/CarteMedecin.vue - un composant ENFANT
  -------------------------------------------------------------------------
  Il reçoit ses données de son parent par des PROPS (propriétés), déclarées
  avec defineProps. Le type TypeScript des props est vérifié à la
  compilation : <CarteMedecin :medecin="42"> serait refusé.

  Règle d'or : un composant ne MODIFIE JAMAIS ses props. Les données
  descendent du parent vers l'enfant ("one-way data flow") ; pour
  demander un changement, l'enfant émet un événement (cf. exemple 08).
  =========================================================================
-->
<script setup lang="ts">
import { computed } from 'vue';
import type { Medecin } from '../medecin';

// withDefaults : une valeur par défaut pour les props facultatives (?)
const props = withDefaults(
  defineProps<{
    medecin: Medecin;
    rang: number;
    compact?: boolean;
  }>(),
  { compact: false },
);

// un computed fondé sur une prop : recalculé si le parent change la prop
const initiales = computed(() => `${props.medecin.prenom[0]}${props.medecin.nom[0]}`);
</script>

<template>
  <div class="card h-100" :class="{ 'border-success': medecin.disponible }">
    <div class="card-body d-flex gap-3 align-items-center">
      <div class="initiales">{{ initiales }}</div>
      <div>
        <!-- dans le template, les props s'utilisent directement par leur nom -->
        <h2 class="h6 mb-1">{{ rang }}. {{ medecin.titre }} {{ medecin.prenom }} {{ medecin.nom }}</h2>
        <p v-if="!compact" class="mb-0 text-muted small">{{ medecin.specialite }}</p>
      </div>
    </div>
  </div>
</template>

<style scoped>
.initiales {
  width: 2.5rem;
  height: 2.5rem;
  border-radius: 50%;
  display: flex;
  align-items: center;
  justify-content: center;
  background: #0d6efd;
  color: white;
  font-weight: bold;
}
</style>
    • ligne 16 : [import type] importe un type seulement : rien de cet import ne subsiste dans le [JavaScript] produit ;
    • lignes 19-26 : [defineProps<{...}>()] déclare les props du composant, c'est-à-dire les données qu'il reçoit de son parent, avec leur type. Une prop suivie de [?] est facultative ; [withDefaults] lui donne une valeur par défaut. [defineProps] n'a pas besoin d'être importée : c'est une « macro » que le compilateur des fichiers [.vue] reconnaît ;
    • ligne 29 : dans le script, on lit les props par l'objet [props]. Le [computed] suit les props : si le parent change le médecin transmis, les initiales sont recalculées ;
    • ligne 38 : dans le template, les props s'utilisent directement par leur nom ;
    • ligne 39 : une prop peut modifier l'affichage.

    <!--
  =========================================================================
  07-composants/src/App.vue - le composant PARENT
  -------------------------------------------------------------------------
  Il importe le composant CarteMedecin et l'utilise comme une nouvelle
  balise HTML, <CarteMedecin>, autant de fois qu'il le faut : un composant
  est un morceau d'interface RÉUTILISABLE, avec ses propres données, son
  template et son style.
  =========================================================================
-->
<script setup lang="ts">
import { ref } from 'vue';
// dans <script setup>, un composant importé est aussitôt utilisable dans le template
import CarteMedecin from './components/CarteMedecin.vue';
import type { Medecin } from './medecin';

const medecins = ref<Medecin[]>([
  { id: 1, titre: 'Mme', prenom: 'Marie', nom: 'PELISSIER', specialite: 'généraliste', disponible: true },
  { id: 2, titre: 'Mr', prenom: 'Paul', nom: 'TATOU', specialite: 'pédiatre', disponible: false },
  { id: 3, titre: 'Melle', prenom: 'Sophie', nom: 'DUPONT', specialite: 'généraliste', disponible: true },
]);
const compact = ref(false);

// le parent modifie SES données : les enfants concernés se mettent à jour
function inverserDisponibilite(): void {
  for (const m of medecins.value) {
    m.disponible = !m.disponible;
  }
}
</script>

<template>
  <div class="container py-4">
    <h1 class="h3 mb-3">Exemple 07 - les composants et leurs props</h1>
    <div class="d-flex gap-3 mb-3">
      <label class="form-check-label"><input v-model="compact" type="checkbox" class="form-check-input"> affichage compact</label>
      <button class="btn btn-sm btn-outline-primary" @click="inverserDisponibilite">Inverser les disponibilités</button>
    </div>
    <div class="row g-3">
      <div v-for="(m, i) in medecins" :key="m.id" class="col-md-4">
        <!-- :medecin="m" transmet l'OBJET m (une expression) ;
             compact, sans deux-points, transmettrait la CHAÎNE "compact" -->
        <CarteMedecin :medecin="m" :rang="i + 1" :compact="compact" />
      </div>
    </div>
  </div>
</template>
    • ligne 14 : dans [<script setup>], un composant importé est aussitôt utilisable dans le template, comme une nouvelle balise ;
    • ligne 43 : chaque carte reçoit SON médecin. [:medecin="m"] (avec deux-points) transmet la valeur de l'expression [m] ; sans les deux-points, on transmettrait la chaîne de caractères ["m"], ce que [TypeScript] refuserait ici. Le nom des balises de composants s'écrit en [PascalCase] pour les distinguer des balises HTML ;
    • lignes 25-29 : le parent modifie SES données ; les cartes concernées se mettent à jour.

    La règle d'or : un composant ne modifie jamais ses props. Les données descendent du parent vers l'enfant ([one-way data flow]) : le parent en est le propriétaire. Pour demander un changement, l'enfant émet un événement, que le parent traite : c'est l'objet de l'exemple suivant.

    <!--
  =========================================================================
  08-evenements-composants/src/components/Compteur.vue
  -------------------------------------------------------------------------
  Un enfant qui PRÉVIENT son parent : defineEmits déclare les événements
  qu'il peut émettre, avec le type de leurs données. Le parent les écoute
  comme des événements HTML : <Compteur @change="..." @limite="...">.
  =========================================================================
-->
<script setup lang="ts">
import { ref } from 'vue';

const props = defineProps<{ libelle: string; max: number }>();

// deux événements : 'change' (avec la nouvelle valeur) et 'limite' (sans donnée)
const emit = defineEmits<{
  change: [valeur: number];
  limite: [];
}>();

const valeur = ref(0);

function plus(): void {
  if (valeur.value >= props.max) {
    emit('limite');
    return;
  }
  valeur.value++;
  emit('change', valeur.value);
}
</script>

<template>
  <div class="d-flex align-items-center gap-2 mb-2">
    <span class="w-25">{{ libelle }}</span>
    <button class="btn btn-sm btn-outline-primary" @click="plus">+1</button>
    <span class="badge text-bg-secondary">{{ valeur }} / {{ max }}</span>
  </div>
</template>
    • lignes 16-19 : [defineEmits] déclare les événements que le composant peut émettre, avec le type de leurs données : [change] transporte un nombre, [limite] rien du tout ;
    • ligne 25 et ligne 29 : l'émission d'un événement. [TypeScript] vérifie le nom de l'événement et le type de sa donnée ;
    • ligne 21 : l'enfant a le droit d'avoir son propre état : [valeur] est à lui, pas au parent.

    <!--
  =========================================================================
  08-evenements-composants/src/components/ChampTexte.vue
  -------------------------------------------------------------------------
  Un champ de formulaire "maison" (libellé + champ + aide + compteur de
  caractères) qui accepte v-model, comme un <input> ordinaire :
      <ChampTexte v-model="nom" libelle="Nom" :max="20" />

  defineModel() crée une ref reliée au v-model du parent : la LIRE donne la
  valeur du parent, l'ÉCRIRE émet l'événement 'update:modelValue', que le
  parent traite en mettant à jour sa donnée. Les données restent donc bien
  la propriété du parent.
  =========================================================================
-->
<script setup lang="ts">
import { useId } from 'vue';

const modele = defineModel<string>({ required: true });
defineProps<{ libelle: string; max: number; aide?: string }>();

// un identifiant unique par instance, pour relier <label for> et <input id>
const id = useId();
</script>

<template>
  <div class="mb-3">
    <label class="form-label" :for="id">{{ libelle }}</label>
    <!-- v-model="modele" : le champ natif est relié à la ref de defineModel -->
    <input :id="id" v-model="modele" class="form-control" :maxlength="max" :class="{ 'is-invalid': modele.length === max }">
    <div class="form-text">{{ aide }} ({{ modele.length }} / {{ max }})</div>
  </div>
</template>
    • ligne 18 : [defineModel] crée une [ref] reliée au [v-model] du parent. La lire donne la valeur du parent ; l'écrire émet l'événement [update:modelValue], que le parent traite en modifiant SA donnée. [v-model="nom"] sur un composant n'est qu'un raccourci pour la prop [modelValue] et cet événement : la donnée reste la propriété du parent ;
    • ligne 22 : [useId()] fournit un identifiant unique par instance du composant : les deux [ChampTexte] de la page n'auront pas le même [id], et chaque [<label for>] désigne bien SON champ ;
    • ligne 29 : le champ natif est relié à la [ref] de [defineModel].

    <!--
  =========================================================================
  08-evenements-composants/src/App.vue - le parent écoute ses enfants
  -------------------------------------------------------------------------
  Deux façons pour un enfant de faire remonter une information :
    1. émettre un événement, que le parent écoute avec @ (Compteur) ;
    2. v-model sur un composant (ChampTexte) : un raccourci pour la prop
       modelValue + l'événement update:modelValue.
  =========================================================================
-->
<script setup lang="ts">
import { computed, ref } from 'vue';
import Compteur from './components/Compteur.vue';
import ChampTexte from './components/ChampTexte.vue';

const total = ref(0);
const message = ref('');
const prenom = ref('Marie');
const nom = ref('PELISSIER');
const nomComplet = computed(() => `${prenom.value} ${nom.value.toUpperCase()}`);

// le gestionnaire de l'événement 'change' : il reçoit la donnée émise
function surChange(libelle: string, valeur: number): void {
  total.value++;
  message.value = `${libelle} vaut maintenant ${valeur}`;
}
</script>

<template>
  <div class="container py-4" style="max-width: 640px">
    <h1 class="h3 mb-3">Exemple 08 - événements et v-model sur un composant</h1>

    <div class="card p-3 mb-4">
      <h2 class="h6">1. Des événements émis par les enfants</h2>
      <Compteur libelle="Cafés" :max="3" @change="(v) => surChange('Cafés', v)" @limite="message = 'Pas plus de 3 cafés !'" />
      <Compteur libelle="Verres d'eau" :max="8" @change="(v) => surChange(`Verres d'eau`, v)" @limite="message = 'Assez bu.'" />
      <p class="mb-0">Total des clics : {{ total }} - <em>{{ message }}</em></p>
    </div>

    <div class="card p-3">
      <h2 class="h6">2. v-model sur un composant</h2>
      <ChampTexte v-model="prenom" libelle="Prénom" :max="20" aide="Obligatoire" />
      <ChampTexte v-model="nom" libelle="Nom" :max="20" aide="Mis en majuscules à l'affichage" />
      <p class="mb-0">Données du parent : <strong>{{ nomComplet }}</strong></p>
      <button class="btn btn-sm btn-outline-secondary mt-2 align-self-start" @click="prenom = ''; nom = ''">Vider (depuis le parent)</button>
    </div>
  </div>
</template>
    • ligne 35 : le parent écoute les événements de ses enfants avec [@], comme des événements HTML. La fonction fléchée [(v) => surChange('Cafés', v)] reçoit la donnée de l'événement ; [@limite] exécute une simple instruction ;
    • ligne 42 : [v-model] sur un composant ;
    • ligne 45 : quand le PARENT vide ses données, les champs suivent : la liaison fonctionne dans les deux sens.

  =========================================================================
  09-slots/src/components/Carte.vue - un GABARIT réutilisable
  -------------------------------------------------------------------------
  Les props transmettent des DONNÉES ; les slots transmettent du CONTENU
  (du HTML, d'autres composants). Carte fixe le cadre (bordure, en-tête,
  pied), le parent fournit ce qu'il y a dedans :
    - <slot />              le slot par défaut : le contenu "principal" ;
    - <slot name="entete">  un slot nommé, rempli par <template #entete> ;
    - le texte placé ENTRE <slot> et </slot> est affiché si le parent ne
      fournit rien (contenu par défaut).
  C'est l'équivalent, côté client, du gabarit layout.hbs et de son {{{body}}}
  dans le cours NestJS.
  =========================================================================
-->
<script setup lang="ts">
defineProps<{ couleur?: 'primary' | 'success' | 'danger' }>();
</script>

<template>
  <div class="card mb-3" :class="couleur ? `border-${couleur}` : ''">
    <div class="card-header" :class="couleur ? `text-bg-${couleur}` : ''">
      <slot name="entete">Sans titre</slot>
    </div>
    <div class="card-body">
      <slot />
    </div>
    <!-- $slots.pied : le parent a-t-il fourni un pied ? Sinon, pas de <div> vide -->
    <div v-if="$slots.pied" class="card-footer text-muted small">
      <slot name="pied" />
    </div>
  </div>
</template>
    • ligne 23 : un slot nommé ; le texte placé entre [<slot>] et [</slot>] est affiché si le parent ne fournit rien ;
    • ligne 26 : le slot par défaut : le contenu « principal » ;
    • ligne 29 : [$slots] dit quels slots le parent a remplis : sans pied, pas de [<div>] vide.

    C'est l'équivalent, côté client, du gabarit [layout.hbs] et de son [{{{body}}}] dans le cours [NestJS].

  =========================================================================
  09-slots/src/components/Tableau.vue - un tableau GÉNÉRIQUE, à slot "scopé"
  -------------------------------------------------------------------------
  generic="T" : un composant générique, comme une classe générique
  TypeScript - il affiche des lignes de n'importe quel type T.

  Le tableau sait parcourir les lignes, mais pas comment afficher une
  ligne : il PASSE chaque ligne à son slot (<slot name="ligne" :ligne="l">),
  et c'est le parent qui dit quoi en faire (<template #ligne="{ ligne }">).
  On parle de slot "scopé" : le contenu fourni par le parent utilise des
  données qui appartiennent à l'enfant.
  =========================================================================
-->
<script setup lang="ts" generic="T extends { id: number }">
defineProps<{ lignes: T[]; colonnes: string[] }>();
</script>

<template>
  <table class="table table-sm align-middle mb-0">
    <thead>
      <tr><th v-for="c in colonnes" :key="c">{{ c }}</th></tr>
    </thead>
    <tbody>
      <tr v-for="(l, i) in lignes" :key="l.id">
        <slot name="ligne" :ligne="l" :index="i" />
      </tr>
      <tr v-if="lignes.length === 0">
        <td :colspan="colonnes.length" class="text-muted"><slot name="vide">Aucune donnée.</slot></td>
      </tr>
    </tbody>
  </table>
</template>
    • ligne 15 : un composant générique, comme une classe générique [TypeScript] : [T] est le type des lignes, dont on exige seulement une propriété [id] (pour la clé du [v-for]) ;
    • ligne 26 : le tableau sait parcourir les lignes, mais pas comment afficher une ligne. Il passe chaque ligne à son slot, et c'est le parent qui l'affiche. On parle de slot « scopé » : le contenu fourni par le parent utilise des données qui appartiennent à l'enfant.

<script setup lang="ts">
import { ref } from 'vue';
import Carte from './components/Carte.vue';
import Tableau from './components/Tableau.vue';

interface Creneau {
  id: number;
  horaire: string;
  patient: string | null;
}

const creneaux = ref<Creneau[]>([
  { id: 1, horaire: '8:00 - 8:20', patient: null },
  { id: 2, horaire: '8:20 - 8:40', patient: 'Mme Alice DURAND' },
  { id: 3, horaire: '8:40 - 9:00', patient: null },
]);
</script>

<template>
  <div class="container py-4" style="max-width: 720px">
    <h1 class="h3 mb-3">Exemple 09 - gabarits et slots</h1>

    <!-- #entete est l'abréviation de v-slot:entete -->
    <Carte couleur="primary">
      <template #entete>Agenda de Mme PELISSIER</template>
      <!-- le slot par défaut : tout ce qui n'est pas dans un <template #...> -->
      <Tableau :lignes="creneaux" :colonnes="['#', 'Créneau', 'Statut']">
        <!-- on récupère les données passées par le Tableau : { ligne, index } -->
        <template #ligne="{ ligne, index }">
          <td>{{ index + 1 }}</td>
          <td>{{ ligne.horaire }}</td>
          <td>
            <span v-if="ligne.patient" class="badge text-bg-secondary">{{ ligne.patient }}</span>
            <span v-else class="badge text-bg-success">Libre</span>
          </td>
        </template>
      </Tableau>
      <template #pied>{{ creneaux.filter((c) => c.patient === null).length }} créneau(x) libre(s)</template>
    </Carte>

    <Carte couleur="success">
      <template #entete>Une carte sans pied</template>
      <p class="mb-0">Le pied n'est pas fourni : la carte ne l'affiche pas.</p>
    </Carte>

    <Carte>
      <!-- pas d'en-tête fourni : le contenu par défaut du slot, « Sans titre » -->
      <Tableau :lignes="[]" :colonnes="['Nom']">
        <template #vide>Personne pour l'instant.</template>
      </Tableau>
    </Carte>

// 11-composables/src/composables/useHorloge.ts - un COMPOSABLE
// -------------------------------------------------------------------------
// Un composable est une simple fonction, dont le nom commence par "use"
// par convention, qui regroupe un état réactif ET la logique qui va avec
// (ici : la minuterie, son démarrage et son arrêt). Tout composant qui
// l'appelle obtient SA propre horloge, sans recopier le code.
//
// C'est la manière Vue.js de partager de la logique entre composants - le
// rôle que tenaient, côté serveur, les services NestJS.
// =========================================================================

import { onMounted, onUnmounted, ref, type Ref } from 'vue';

export function useHorloge(periodeMs = 1000): { maintenant: Ref<Date> } {
  const maintenant = ref(new Date());
  let minuterie: number | undefined;

  // les hooks de cycle de vie s'attachent au composant qui APPELLE le composable
  onMounted(() => {
    minuterie = window.setInterval(() => (maintenant.value = new Date()), periodeMs);
  });
  onUnmounted(() => window.clearInterval(minuterie));

  return { maintenant };
}

// 12-confirmation/src/composables/useConfirmation.ts
// -------------------------------------------------------------------------
// « Êtes-vous sûr ? » : window.confirm() existe, mais on ne peut ni le
// mettre en forme, ni traduire ses boutons. On le remplace par une fenêtre
// Bootstrap (FenetreConfirmation.vue), pilotée par ce composable.
//
// L'astuce : confirmer(message) renvoie une PROMESSE, résolue à true (Oui)
// ou false (Non) quand l'utilisateur répond. Le code appelant s'écrit
// alors aussi simplement qu'avec window.confirm :
//
//     if (await confirmer('Supprimer ce médecin ?')) { ... }
//
// L'état (message affiché, fonction à appeler à la réponse) est déclaré
// HORS de la fonction : il est donc UNIQUE pour toute l'application. Une
// seule fenêtre, placée une fois dans App.vue, sert tous les composants.
// =========================================================================

import { readonly, ref } from 'vue';

const message = ref<string | null>(null); // null : fenêtre fermée
let repondre: ((reponse: boolean) => void) | null = null;

export function useConfirmation() {
  function confirmer(texte: string): Promise<boolean> {
    message.value = texte;
    return new Promise<boolean>((resolve) => {
      repondre = resolve;
    });
  }

  function reponse(oui: boolean): void {
    message.value = null;
    repondre?.(oui);
    repondre = null;
  }

  // readonly : les composants lisent le message, seul le composable le modifie
  return { message: readonly(message), confirmer, reponse };
}

import { useConfirmation } from './composables/useConfirmation';

interface Contact {
  id: number;
  nom: string;
}

const contacts = ref<Contact[]>([
  { id: 1, nom: 'Jean MARTIN' },
  { id: 2, nom: 'Alice DURAND' },
  { id: 3, nom: 'Luc GERMAN' },
]);
const message = ref('');
const { confirmer } = useConfirmation();

// une fonction async : elle "attend" la réponse de l'utilisateur
async function supprimer(c: Contact): Promise<void> {
  if (!(await confirmer(`Supprimer le contact ${c.nom} ?`))) {
    message.value = 'Suppression abandonnée.';
    return;
  }
  contacts.value = contacts.value.filter((x) => x.id !== c.id);
  message.value = `${c.nom} a été supprimé.`;
}

async function toutSupprimer(): Promise<void> {
  if (await confirmer(`Supprimer les ${contacts.value.length} contacts ?`)) {
    contacts.value = [];
    message.value = 'Tous les contacts ont été supprimés.';
  }
}
</script>

<template>
  <div class="container py-4" style="max-width: 640px">
    <h1 class="h3 mb-3">Exemple 12 - une fenêtre de confirmation</h1>
    <ul class="list-group mb-3">
      <li v-for="c in contacts" :key="c.id" class="list-group-item d-flex justify-content-between align-items-center">
        {{ c.nom }}
        <button class="btn btn-sm btn-outline-danger" @click="supprimer(c)">Supprimer</button>
      </li>
      <li v-if="contacts.length === 0" class="list-group-item text-muted">Aucun contact.</li>
    </ul>
    <button class="btn btn-danger" :disabled="contacts.length === 0" @click="toutSupprimer">Tout supprimer</button>
    <p v-if="message" class="alert alert-info mt-3">{{ message }}</p>
  </div>
  <!-- la fenêtre, UNE fois pour toute l'application -->
  <FenetreConfirmation />
</template>
