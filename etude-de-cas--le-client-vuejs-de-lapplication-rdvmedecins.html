    10. Étude de cas : le client Vue.js de l'application RdvMedecins

    10.1. Le problème

    L'application [RdvMedecins] permet de prendre des rendez-vous dans un cabinet médical. Le cours [NestJS] l'a écrite sous la forme d'une application HTML, dont le serveur fabriquait les pages. Nous en écrivons ici le client [Vue.js] : les MÊMES pages, fabriquées dans le navigateur, à partir des données JSON du serveur présenté au chapitre « Le serveur RdvMedecins, une boîte noire ».

    Le client doit offrir tout ce qu'offrait l'application HTML :

    • une page de connexion, protégée par un captcha, avec la possibilité de créer un compte de patient ;
    • l'agenda d'un médecin pour un jour donné, avec réservation (fenêtre de choix du patient) et annulation ;
    • pour l'administrateur, la gestion des médecins et des clients (liste, ajout, modification, suppression) ;
    • pour le patient, son espace (son rendez-vous à venir, qu'il peut annuler) et la gestion de son compte ;
    • deux langues, le français et l'anglais ;
    • des adresses propres ([/agenda?idMedecin=1&jour=...]), qu'on peut recharger, mettre en favori, et parcourir avec les boutons Précédent / Suivant du navigateur.

    10.2. Installation et exécution

    Le serveur JSON doit être installé et lancé (cf. chapitre précédent). Pour utiliser le client dans un navigateur, on n'a PAS besoin du mode test du captcha : on peut laisser [CAPTCHA_TEST] vide dans le fichier [.env] du serveur.

    Dans une console ouverte sur le dossier [rdvmedecins-vuejs] :

    npm install
npm run dev

    puis on ouvre http://localhost:5173 dans un navigateur. Les comptes de démonstration sont rappelés sur la page de connexion (mot de passe = login).

    Le serveur de [Vite] des exemples utilise aussi le port 5173. Si ce port est déjà occupé, [Vite] en prend un autre (5174...) et l'affiche dans la console : il faut alors ouvrir cette adresse-là.

// vite.config.ts
// -------------------------------------------------------------------------
//   - npm run dev   : serveur de développement sur http://localhost:5173 ;
//                     les requêtes /api/... sont transmises au serveur JSON
//                     (port 8080) par le proxy : page et API ont la même
//                     origine, le cookie du jeton circule normalement ;
//   - npm run build : l'application compilée, dans dist/. Pour la mettre en
//                     production, on copie le CONTENU de dist/ dans le dossier
//                     client/ du serveur JSON, qui la sert alors lui-même
//                     (cf. chapitre "Déploiement").
// =========================================================================

import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';

export default defineConfig({
  plugins: [vue()],
  server: {
    port: 5173,
    proxy: {
      '/api': 'http://localhost:8080',
    },
  },
  // npm run preview : sert dist/ (après npm run build), avec le même proxy
  preview: {
    port: 4173,
    proxy: {
      '/api': 'http://localhost:8080',
    },
  },
});

    • lignes 26-31 : le même proxy pour [npm run preview].

    // =========================================================================
// main.ts - le démarrage de l'application
// -------------------------------------------------------------------------
//   1. Bootstrap (CSS) et nos quelques styles ;
//   2. Pinia (stores), vue-i18n (langues), le routeur ;
//   3. la réaction à une réponse 401 venue de n'importe quelle requête :
//      la session a expiré - on oublie l'utilisateur et on retourne à la
//      page de connexion, avec un message ;
//   4. l'affichage dans <div id="app">.
// =========================================================================

import { createApp } from 'vue';
import { createPinia } from 'pinia';
import 'bootstrap/dist/css/bootstrap.min.css';
import './styles.css';
import App from './App.vue';
import { i18n } from './i18n';
import { router } from './router';
import { quandNonAuthentifie } from './api/client-http';
import { useSessionStore } from './stores/session';
import { useMessagesStore } from './stores/messages';

const app = createApp(App);
app.use(createPinia());
app.use(i18n);
app.use(router);

quandNonAuthentifie(() => {
  useSessionStore().oublier();
  useMessagesStore().flash('erreur', 'ERRORS.SESSION_EXPIRED');
  router.push({ name: 'login' });
});

app.mount('#app');
    • lignes 24-26 : les trois extensions : les stores, les langues, le routeur. [Pinia] doit être installée AVANT le routeur : le garde du routeur utilise un store ;
    • lignes 28-32 : ce qu'il faut faire quand une requête, n'importe laquelle, reçoit la réponse 401 (session expirée, compte supprimé...) : oublier l'utilisateur, préparer le message « Votre session a expiré » pour la page suivante, et aller à la page de connexion. Cette réaction est déclarée UNE fois, ici ; la fonction [quandNonAuthentifie] est décrite avec [client-http.ts].

    // =========================================================================
// api/client-http.ts - la fonction qui envoie TOUTES les requêtes à l'API
// -------------------------------------------------------------------------
// Reprise de commun/api.ts des exemples, avec une nouveauté : la gestion
// centralisée de la réponse 401.
//
// Un 401 peut arriver n'importe quand : le jeton a expiré (2 heures), le
// compte a été supprimé, le serveur a redémarré avec une autre clé
// secrète... Plutôt que de traiter ce cas dans chaque composant, on
// prévient UNE fonction, enregistrée au démarrage (cf. main.ts), qui oublie
// l'utilisateur et renvoie vers la page de connexion.
// =========================================================================

export class ErreurApi extends Error {
  constructor(
    public readonly statusCode: number, // 0 : le serveur n'a pas répondu
    public readonly cle: string, // clé de traduction : 'ERRORS.LOGIN_TAKEN'
    public readonly params: Record<string, string> = {},
    public readonly champs: Record<string, string> = {}, // erreur de chaque champ
  ) {
    super(cle);
    this.name = 'ErreurApi';
  }
}

// la fonction appelée à chaque réponse 401 (cf. main.ts)
let surNonAuthentifie: (erreur: ErreurApi) => void = () => {};

export function quandNonAuthentifie(fonction: (erreur: ErreurApi) => void): void {
  surNonAuthentifie = fonction;
}

type Methode = 'GET' | 'POST' | 'PUT' | 'DELETE';

export interface OptionsRequete {
  // les routes publiques (connexion, captcha...) et GET /api/auth/moi
  // traitent le 401 elles-mêmes : pas de redirection automatique
  ignorer401?: boolean;
}

export async function requete<T>(methode: Methode, url: string, corps?: unknown, options: OptionsRequete = {}): Promise<T> {
  let reponse: Response;
  try {
    reponse = await fetch(`/api${url}`, {
      method: methode,
      headers: corps !== undefined ? { 'Content-Type': 'application/json', Accept: 'application/json' } : { Accept: 'application/json' },
      body: corps !== undefined ? JSON.stringify(corps) : undefined,
    });
  } catch {
    throw new ErreurApi(0, 'ERRORS.SERVER_UNREACHABLE');
  }

  // lu comme du texte puis converti : une réponse vide, ou qui n'est pas du
  // JSON (serveur arrêté : c'est le proxy de Vite qui répond), ne fait pas
  // planter l'application
  const texte = await reponse.text();
  let donnees: unknown = null;
  try {
    donnees = texte ? JSON.parse(texte) : null;
  } catch {
    donnees = null;
  }

  if (reponse.ok) {
    return donnees as T;
  }

  const e = (donnees ?? {}) as { cle?: string; params?: Record<string, string>; champs?: Record<string, string> };
  const erreur = new ErreurApi(
    reponse.status,
    // pas de clé : ce n'est pas notre serveur qui a répondu, mais un proxy
    // (Vite : 500 sans corps ; nginx : 502, 504...)
    e.cle ?? (reponse.status >= 500 ? 'ERRORS.SERVER_UNREACHABLE' : 'ERRORS.SERVER_ERROR'),
    e.params,
    e.champs,
  );
  if (reponse.status === 401 && !options.ignorer401) {
    surNonAuthentifie(erreur);
  }
  throw erreur;
}

    • ligne 46 : l'entête [Accept] indique au serveur le format de réponse souhaité ;

    • ligne 73 : une réponse sans clé ne vient pas de notre serveur : quand le serveur JSON est arrêté, c'est le proxy qui répond (celui de [Vite] par une erreur 500 sans corps ; un proxy de production comme [nginx], par 502 ou 504) ;

    // =========================================================================
// stores/session.ts - QUI est connecté ?
// -------------------------------------------------------------------------
// Le store Pinia de la session : l'utilisateur connecté (ou null), et ce
// qu'on en déduit (est-il ADMIN ? patient ?).
//
// Le jeton JWT lui-même n'est PAS ici : il est dans un cookie httpOnly que
// seul le navigateur manipule. Le store ne garde que la DESCRIPTION de
// l'utilisateur, renvoyée par le serveur ({ login, nom, role }).
//
// Au démarrage (et après un F5), le store est vide : verifier() demande au
// serveur, une seule fois, qui est connecté (GET /api/auth/moi).
// =========================================================================

import { computed, ref } from 'vue';
import { defineStore } from 'pinia';
import { rdvApi } from '../api/rdvmedecins.api';
import type { Role, Utilisateur } from '../api/types';

export const useSessionStore = defineStore('session', () => {
  const utilisateur = ref<Utilisateur | null>(null);
  // la question "qui est connecté ?" a-t-elle déjà été posée au serveur ?
  let verification: Promise<void> | null = null;

  const connecte = computed(() => utilisateur.value !== null);
  const role = computed<Role | null>(() => utilisateur.value?.role ?? null);
  const estAdmin = computed(() => role.value === 'ADMIN');
  const estPatient = computed(() => role.value === 'USER');
  // ADMIN et DOCTOR : prennent et annulent les rendez-vous de n'importe quel patient
  const estGestionnaire = computed(() => role.value === 'ADMIN' || role.value === 'DOCTOR');

  // la page d'accueil de chaque rôle, juste après la connexion
  const pageAccueil = computed(() => (estPatient.value ? '/mon-espace' : '/agenda'));

  // appelée par le garde du routeur avant CHAQUE navigation ; ne questionne
  // le serveur que la première fois (la promesse est gardée et réutilisée)
  function verifier(): Promise<void> {
    verification ??= rdvApi
      .moi()
      .then((u) => {
        utilisateur.value = u;
      })
      .catch(() => {
        utilisateur.value = null; // 401 : personne ; ou serveur injoignable
      });
    return verification;
  }

  async function connecter(login: string, password: string, captchaId: string, captcha: string): Promise<void> {
    utilisateur.value = await rdvApi.connecter(login, password, captchaId, captcha);
  }

  // l'utilisateur a changé de nom ou de login (PUT /api/mon-compte)
  function mettreAJour(u: Utilisateur): void {
    utilisateur.value = u;
  }

  async function deconnecter(): Promise<void> {
    try {
      await rdvApi.deconnecter();
    } finally {
      oublier();
    }
  }

  // sans rien demander au serveur : session expirée, compte supprimé
  function oublier(): void {
    utilisateur.value = null;
  }

  return {
    utilisateur,
    connecte,
    role,
    estAdmin,
    estPatient,
    estGestionnaire,
    pageAccueil,
    verifier,
    connecter,
    mettreAJour,
    deconnecter,
    oublier,
  };
});
    • ligne 21 : l'utilisateur connecté, tel que le serveur le décrit. Le jeton, lui, n'est pas là : il est dans un cookie que seul le navigateur manipule ;
    • lignes 25-30 : ce qu'on en déduit, utilisé par les pages et la barre de navigation ;
    • ligne 33 : la page d'accueil de chaque rôle : « Mon espace » pour un patient, l'agenda pour les autres ;
    • lignes 37-47 : la question « qui est connecté ? », posée au serveur la PREMIÈRE fois seulement. La promesse est gardée dans [verification] : les appels suivants la réutilisent (l'opérateur [??=] n'affecte que si la variable vaut [null] ou [undefined]). Elle ne peut pas échouer : une erreur (401, serveur injoignable) signifie « personne » ;
    • lignes 49-51 : la connexion. En cas d'échec, [rdvApi.connecter] rejette sa promesse avec une [ErreurApi], qui traverse cette fonction jusqu'à la page de connexion ;
    • ligne 54 : après une modification de son compte, le patient a peut-être changé de nom ;
    • lignes 58-64 : [finally] : on oublie l'utilisateur, même si le serveur n'a pas répondu ;
    • ligne 67 : sans rien demander au serveur (session expirée, compte supprimé).

    // =========================================================================
// stores/messages.ts - les messages affichés à l'utilisateur
// -------------------------------------------------------------------------
// Même présentation que l'application HTML :
//   - un SUCCÈS s'affiche en HAUT de la page (bandeau vert) ;
//   - une ERREUR en BAS, sur fond rose léger (zone "collante").
// Un message est une CLÉ de traduction (+ ses paramètres) : il se retraduit
// donc tout seul si l'utilisateur change de langue.
//
// Les messages "flash" : une action qui se termine par un changement de
// page (réservation, ajout d'un médecin...) dépose son message avec flash() ;
// il s'affichera sur la page SUIVANTE, puis disparaîtra à la navigation
// d'après (cf. router.afterEach dans router.ts). C'était, côté serveur, le
// rôle du cookie de courte durée "rdvmedecins_flash".
// =========================================================================

import { ref } from 'vue';
import { defineStore } from 'pinia';
import { ErreurApi } from '../api/client-http';

export interface Message {
  cle: string;
  params?: Record<string, string>;
}

export const useMessagesStore = defineStore('messages', () => {
  const succes = ref<Message | null>(null);
  const erreur = ref<Message | null>(null);
  // les messages à afficher sur la page suivante
  let enAttente: { succes: Message | null; erreur: Message | null } | null = null;

  function afficherSucces(cle: string, params?: Record<string, string>): void {
    succes.value = { cle, params };
    erreur.value = null;
  }

  function afficherErreur(cle: string, params?: Record<string, string>): void {
    erreur.value = { cle, params };
    succes.value = null;
  }

  // une ErreurApi -> le message de la page ; toute autre erreur est une
  // anomalie du client, qu'on laisse remonter (console du navigateur)
  function afficherErreurApi(e: unknown): void {
    if (!(e instanceof ErreurApi)) {
      throw e;
    }
    afficherErreur(e.cle, e.params);
  }

  function effacer(): void {
    succes.value = null;
    erreur.value = null;
  }

  // pour la page SUIVANTE
  function flash(type: 'succes' | 'erreur', cle: string, params?: Record<string, string>): void {
    enAttente ??= { succes: null, erreur: null };
    enAttente[type] = { cle, params };
  }

  // appelée après chaque navigation (router.afterEach)
  function nouvellePage(): void {
    succes.value = enAttente?.succes ?? null;
    erreur.value = enAttente?.erreur ?? null;
    enAttente = null;
  }

  return { succes, erreur, afficherSucces, afficherErreur, afficherErreurApi, effacer, flash, nouvellePage };
});
    • lignes 21-24 : un message est une CLÉ de traduction et ses paramètres. Il se retraduit donc tout seul si l'utilisateur change de langue ;
    • lignes 27-28 : le message de succès (affiché en haut) et le message d'erreur (en bas) de la page courante ;
    • lignes 44-49 : une [ErreurApi] devient le message de la page. Toute autre erreur est une anomalie du CLIENT (une faute de programmation) : on la laisse remonter, elle s'affichera dans la console du navigateur ;
    • lignes 57-60 : un message pour la page SUIVANTE. Une action qui se termine par un changement de page (réservation, ajout d'un médecin, connexion après création de compte) le dépose avant de naviguer ;
    • lignes 63-67 : appelée après chaque navigation (cf. [router.ts]) : les messages de la page précédente disparaissent, les messages en attente apparaissent. C'était, dans l'application HTML, le rôle du cookie de courte durée [rdvmedecins_flash].

// Repris de l'exemple 12 : confirmer(cle) ouvre la fenêtre de confirmation
// (components/FenetreConfirmation.vue, placée une fois dans App.vue) et
// renvoie une promesse résolue à true (Oui) ou false (Non). Le message est
// une CLÉ de traduction : la fenêtre le traduit dans la langue courante.
//
//     if (await confirmer('AGENDA.CANCEL_CONFIRM')) { ... }
// =========================================================================

import { readonly, ref } from 'vue';
import { useMessagesStore } from '../stores/messages';

const cleMessage = ref<string | null>(null); // null : fenêtre fermée
let repondre: ((oui: boolean) => void) | null = null;

export function useConfirmation() {
  function confirmer(cle: string): Promise<boolean> {
    repondre?.(false); // une question encore ouverte ? elle vaut "non"
    // une nouvelle question : les messages de l'action précédente sont périmés
    useMessagesStore().effacer();
    cleMessage.value = cle;
    return new Promise<boolean>((resolve) => {
      repondre = resolve;
    });
  }

  function reponse(oui: boolean): void {
    cleMessage.value = null;
    const r = repondre;
    repondre = null;
    r?.(oui);
  }

  return { cleMessage: readonly(cleMessage), confirmer, reponse };
}

    • ligne 20 : une question encore ouverte (cas improbable) reçoit la réponse « non » ;
    • ligne 22 : une nouvelle question rend périmés les messages de l'action précédente.

// composables/useFormatage.ts - l'affichage des personnes, heures et jours
// -------------------------------------------------------------------------
// Le serveur envoie des données BRUTES (hdebut: 8, mdebut: 0 ; jour:

import { useI18n } from 'vue-i18n';
import type { Creneau, Identite } from '../api/types';

// "Mme Alice DURAND"
export function libelle(p: Identite): string {
  return `${p.titre} ${p.prenom} ${p.nom}`;
}

// "8:05" plutôt que "8:5"
export function heure(h: number, m: number): string {
  return `${h}:${String(m).padStart(2, '0')}`;
}

// "8:00 - 8:20"
export function horaire(c: Creneau): string {
  return `${heure(c.hdebut, c.mdebut)} - ${heure(c.hfin, c.mfin)}`;
}

// la date du jour, au format "yyyy-MM-dd" (celui de <input type="date"> et de l'API)
export function aujourdhui(): string {
  const d = new Date();
  return `${d.getFullYear()}-${String(d.getMonth() + 1).padStart(2, '0')}-${String(d.getDate()).padStart(2, '0')}`;
}

// vrai si [jour] est une date qui existe au format yyyy-MM-dd
export function estUneDateValide(jour: unknown): jour is string {
  if (typeof jour !== 'string' || !/^\d{4}-\d{2}-\d{2}$/.test(jour)) {
    return false;
  }
  const date = new Date(`${jour}T00:00:00Z`);
  return !isNaN(date.getTime()) && date.toISOString().slice(0, 10) === jour;
}

export function useFormatage() {
  const { locale } = useI18n();

  // "lundi 5 octobre 2026" / "Monday 5 October 2026"
  function jourLong(jour: string): string {
    return new Intl.DateTimeFormat(locale.value === 'en' ? 'en-GB' : 'fr-FR', {
      dateStyle: 'full',
      timeZone: 'UTC', // "2026-10-05T00:00:00Z" doit rester le 5, quel que soit le fuseau
    }).format(new Date(`${jour}T00:00:00Z`));
  }

  return { libelle, heure, horaire, jourLong };
}

// composables/useFormulaire.ts - les erreurs d'un formulaire envoyé au serveur
// -------------------------------------------------------------------------
// Tous les formulaires de l'application suivent le même schéma que
// l'exemple 20 : aucune règle n'est vérifiée dans le navigateur (elles
// vivent en UN seul endroit, le serveur), et en cas de refus :
//   - l'erreur de chaque champ (ErreurApi.champs) s'affiche sous le champ,
//     encadré de rouge ;
//   - le message général (ErreurApi.cle) s'affiche en bas de la page.

import { ref } from 'vue';
import { ErreurApi } from '../api/client-http';
import { useMessagesStore } from '../stores/messages';

export function useFormulaire() {
  const messages = useMessagesStore();
  const erreurs = ref<Record<string, string>>({}); // champ -> clé du message
  const params = ref<Record<string, string>>({}); // paramètres des messages ({min}...)
  const envoiEnCours = ref(false);

  function effacerErreurs(): void {
    erreurs.value = {};
    params.value = {};
  }

  // exécute l'envoi ; renvoie true s'il a réussi. En cas d'ErreurApi, les
  // erreurs sont affichées et on renvoie false.
  async function envoyer(action: () => Promise<void>): Promise<boolean> {
    effacerErreurs();
    envoiEnCours.value = true;
    try {
      await action();
      return true;
    } catch (e) {
      if (e instanceof ErreurApi) {
        erreurs.value = e.champs;
        params.value = e.params;
      }
      messages.afficherErreurApi(e);
      return false;
    } finally {
      envoiEnCours.value = false;
    }
  }

  return { erreurs, params, envoiEnCours, envoyer, effacerErreurs };
}

    • lignes 30-46 : exécute l'envoi (une fonction fournie par la page) ; en cas d'[ErreurApi], range les erreurs des champs, affiche le message général en bas de la page, et renvoie [false].

// -------------------------------------------------------------------------
// Les MÊMES adresses que l'application HTML (/login, /agenda, /medecins,
// /mon-espace...), mais ce sont maintenant des routes du CLIENT :

//   - type    : 'medecins' ou 'clients' pour les pages communes aux deux.
//
// RAPPEL : ces contrôles ne sont qu'un CONFORT (ne pas afficher une page

  interface RouteMeta {

router.beforeEach(async (vers) => {
  const session = useSessionStore();
  // la première fois (démarrage, F5) : on demande au serveur qui est connecté
  await session.verifier();

  if (vers.meta.public) {
    // déjà connecté : la page de connexion n'a plus de sens
    if (vers.name === 'login' && session.connecte) {
      return session.pageAccueil;
    }
    return true;
  }
  if (!session.connecte) {
    // on retient la page demandée, pour y revenir après la connexion
    return { name: 'login', query: { redirect: vers.fullPath } };
  }
  if (vers.meta.roles && !vers.meta.roles.includes(session.role!)) {
    return { name: 'interdit' };
  }
  return true;
});

  // page précédente disparaissent, les messages flash apparaissent
  if (vers.fullPath !== depuis.fullPath) {
    useMessagesStore().nouvellePage();
  }
  document.title = `${i18n.global.t(vers.meta.titre)} - ${i18n.global.t('APP.TITLE')}`;
});

import { useI18n } from 'vue-i18n';
import { useConfirmation } from '../composables/useConfirmation';

const { t } = useI18n();
const { cleMessage, reponse } = useConfirmation();
const fenetre = useTemplateRef<HTMLElement>('fenetre');
const boutonNon = useTemplateRef<HTMLButtonElement>('boutonNon');
let focusPrecedent: HTMLElement | null = null;

    focusPrecedent = document.activeElement as HTMLElement | null;
    await nextTick(); // la fenêtre est maintenant dans la page
    boutonNon.value?.focus();

    focusPrecedent?.focus();
    focusPrecedent = null;

});

      e.preventDefault();
      dernier?.focus();

      e.preventDefault();
      premier?.focus();

<script setup lang="ts">
import { onMounted, reactive, ref, useTemplateRef } from 'vue';
import { useRoute, useRouter } from 'vue-router';
import { useI18n } from 'vue-i18n';
import { ErreurApi } from '../api/client-http';
import { rdvApi } from '../api/rdvmedecins.api';
import { useSessionStore } from '../stores/session';
import { useMessagesStore } from '../stores/messages';
import ChampCaptcha from '../components/ChampCaptcha.vue';

const { t } = useI18n();
const route = useRoute();
const router = useRouter();
const session = useSessionStore();
const messages = useMessagesStore();

const saisie = reactive({
  login: typeof route.query.login === 'string' ? route.query.login.slice(0, 30) : '',
  password: '',
  captcha: '',
});
const erreurCaptcha = ref<string | undefined>(undefined);
const envoiEnCours = ref(false);
const champCaptcha = useTemplateRef<InstanceType<typeof ChampCaptcha>>('champCaptcha');
const champLogin = useTemplateRef<HTMLInputElement>('champLogin');
const champPassword = useTemplateRef<HTMLInputElement>('champPassword');

// message d'erreur et NOUVELLE image (chacune ne sert qu'une fois)
async function tenter(action: () => Promise<void>): Promise<void> {
  messages.effacer();
  erreurCaptcha.value = undefined;
  envoiEnCours.value = true;
  try {
    await action();
  } catch (e) {
    messages.afficherErreurApi(e);
    if (e instanceof ErreurApi) {
      erreurCaptcha.value = e.champs.captcha;
    }
    await champCaptcha.value?.recharger();
  } finally {
    envoiEnCours.value = false;
  }
}

function seConnecter(): Promise<void> {
  return tenter(async () => {
    await session.connecter(saisie.login.trim(), saisie.password, champCaptcha.value?.captchaId() ?? '', saisie.captcha);
    const redirect = route.query.redirect;
    // seulement un chemin INTERNE : jamais de redirection vers un autre site
    router.push(typeof redirect === 'string' && redirect.startsWith('/') && !redirect.startsWith('//') ? redirect : session.pageAccueil);
  });
}

function creerCompte(): Promise<void> {
  return tenter(async () => {
    await rdvApi.accesInscription(champCaptcha.value?.captchaId() ?? '', saisie.captcha);
    router.push({ name: 'inscription' });
  });
}

<script setup lang="ts">
import { computed, onMounted, reactive, ref, watch } from 'vue';
import { RouterLink, useRoute, useRouter } from 'vue-router';
import { useI18n } from 'vue-i18n';
import { ErreurApi } from '../api/client-http';
import { rdvApi } from '../api/rdvmedecins.api';
import type { Agenda, CreneauAgenda, Personne } from '../api/types';
import { aujourdhui, estUneDateValide, libelle, useFormatage } from '../composables/useFormatage';
import { useConfirmation } from '../composables/useConfirmation';
import { useSessionStore } from '../stores/session';
import { useMessagesStore } from '../stores/messages';
import FenetreReservation from '../components/FenetreReservation.vue';

const route = useRoute();
const router = useRouter();
const session = useSessionStore();
const messages = useMessagesStore();
const { horaire, jourLong } = useFormatage();
const { confirmer } = useConfirmation();

const medecins = ref<Personne[]>([]);
const clients = ref<Personne[]>([]); // ADMIN / DOCTOR : pour la fenêtre de réservation
const agenda = ref<Agenda | null>(null);
const chargement = ref(false);
const envoiEnCours = ref(false);

// les valeurs du formulaire "médecin + jour", recopiées depuis l'URL
const choix = reactive<{ idMedecin: number | null; jour: string }>({ idMedecin: null, jour: aujourdhui() });

// "3" -> 3 ; "", "abc", "-2", absent -> null
function entierPositif(valeur: unknown): number | null {
  const n = Number(valeur);
  return typeof valeur === 'string' && valeur !== '' && Number.isInteger(n) && n > 0 ? n : null;
}

// l'agenda affiché, sans fenêtre de réservation : la query de "retour"
const queryAgenda = computed(() => ({ idMedecin: String(choix.idMedecin ?? ''), jour: choix.jour }));

// le créneau dont la fenêtre de réservation est ouverte (?reserver=7),
// seulement s'il est réservable par cet utilisateur
const creneauAReserver = computed<CreneauAgenda | null>(() => {
  const id = entierPositif(route.query.reserver);
  return agenda.value?.creneaux.find((c) => c.id === id && c.reservable) ?? null;
});

// -------------------------------------------------------------------------
// chargements
// -------------------------------------------------------------------------
onMounted(async () => {
  try {
    medecins.value = await rdvApi.lister('medecins');
    // la liste des patients : seulement pour ceux qui ont le droit de la lire
    if (session.estGestionnaire) {
      clients.value = await rdvApi.lister('clients');
    }
  } catch (e) {
    messages.afficherErreurApi(e);
  }
});

// l'agenda suit l'URL (médecin et jour)
watch(() => [route.query.idMedecin, route.query.jour], chargerAgenda, { immediate: true });

async function chargerAgenda(): Promise<void> {
  // le jour : celui de l'URL s'il est valide, sinon aujourd'hui
  const jourBrut = route.query.jour;
  choix.jour = aujourdhui();
  if (jourBrut !== undefined) {
    if (!estUneDateValide(jourBrut)) {
      agenda.value = null;
      messages.afficherErreur('ERRORS.INVALID_DATE');
      return;
    }
    choix.jour = jourBrut;
  }
  // le médecin : celui de l'URL ; sans médecin, un DOCTOR voit SON agenda
  // (le serveur le retrouve à partir du jeton)
  choix.idMedecin = entierPositif(route.query.idMedecin);
  if (choix.idMedecin === null && session.role !== 'DOCTOR') {
    agenda.value = null;
    return;
  }
  chargement.value = true;
  try {
    agenda.value = await rdvApi.agenda(choix.idMedecin, choix.jour);
    choix.idMedecin = agenda.value.medecin.id;
  } catch (e) {
    agenda.value = null;
    messages.afficherErreurApi(e);
  } finally {
    chargement.value = false;
  }
}

// -------------------------------------------------------------------------
// actions
// -------------------------------------------------------------------------

// "Voir l'agenda" : on change l'URL, l'agenda suit (watch ci-dessus)
function voirAgenda(): void {
  router.push({ query: queryAgenda.value });
}

function fermerReservation(): void {
  router.push({ query: queryAgenda.value });
}

async function reserver(idClient: number | null): Promise<void> {
  const creneau = creneauAReserver.value;
  if (creneau === null) {
    return;
  }
  envoiEnCours.value = true;
  try {
    await rdvApi.reserver(choix.jour, creneau.id, session.estGestionnaire ? idClient : null);
    messages.flash('succes', 'AGENDA.BOOKED');
  } catch (e) {
    if (e instanceof ErreurApi && e.cle === 'ERRORS.CHOOSE_PATIENT') {
      // aucun patient choisi : la fenêtre reste ouverte
      messages.afficherErreur(e.cle);
      return; // (finally s'exécute quand même)
    }
    if (!(e instanceof ErreurApi)) {
      throw e;
    }
    // créneau pris entre-temps, patient qui a déjà un rendez-vous... :
    // le message s'affichera sur l'agenda, fenêtre fermée
    messages.flash('erreur', e.cle, e.params);
  } finally {
    envoiEnCours.value = false;
  }
  await router.push({ query: queryAgenda.value });
  await chargerAgenda(); // c'est le serveur qui fait foi : on relit l'agenda
}

async function annuler(c: CreneauAgenda): Promise<void> {
  if (c.idRv === null || !(await confirmer('AGENDA.CANCEL_CONFIRM'))) {
    return;
  }
  try {
    await rdvApi.annulerRv(c.idRv);
    messages.afficherSucces('AGENDA.CANCELLED');
  } catch (e) {
    messages.afficherErreurApi(e);
  }
  await chargerAgenda();
}

    // le serveur a délivré un NOUVEAU jeton (nom, login) : la barre de
    // navigation doit suivre
    session.mettreAJour(await rdvApi.modifierMonCompte(saisie));
    messages.flash('succes', 'MON_COMPTE.UPDATED');
  });
  // jamais de mot de passe laissé dans les champs après un envoi
  saisie.motDePasseActuel = '';
  if (reussi) {
    router.push('/mon-espace');
  }
}

async function supprimer(): Promise<void> {
  if (!(await confirmer('MON_COMPTE.DELETE_CONFIRM'))) {
    return;
  }
  const reussi = await suppression.envoyer(async () => {
    await rdvApi.supprimerMonCompte(motDePasseSuppression.value);
  });
  motDePasseSuppression.value = '';
  if (reussi) {
    session.oublier(); // le serveur a effacé le cookie du jeton
    messages.flash('succes', 'MON_COMPTE.DELETED');
    router.push({ name: 'login' });
  }
}
